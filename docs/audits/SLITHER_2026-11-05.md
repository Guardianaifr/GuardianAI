# Slither static analysis — 2026-11-05

**This is automated static analysis triaged by the team, not a third-party audit.** The contracts remain unaudited.

- Tool: Slither 0.11.5, 100 detectors, run from `contracts/` with `slither.config.json` (`naming-convention` excluded; `mocks/`, `interfaces/`, `node_modules/` filtered).
- Scope: 77 contracts analyzed (includes OpenZeppelin dependencies and two test helpers that live outside `mocks/`).
- Result: 47 findings — 1 High, 13 Medium, 21 Low, 14 Informational.
- Reproduce: `cd contracts && slither .`

## High (1) — false positive

| Detector | Location | Triage |
| :--- | :--- | :--- |
| `arbitrary-send-eth` | `GuardianAgentWallet._call` | Intended: executing an arbitrary call with value is the wallet's job. Every caller path first requires the operator key, a GuardianAI EIP-712 attestation bound to target/value/calldata hash and nonce, and `_enforceSpendPolicy` (daily cap, target/selector allowlist, threat oracle). `ownerExecute` is the documented owner recovery path. |

## Medium (13) — no exploitable issue found

| Detector | Location | Triage |
| :--- | :--- | :--- |
| `uninitialized-local` | `GuardianAgentWallet._enforceSpendPolicy` (`sel`) | Zero-initialized by design; only assigned when `data.length >= 4`, and the allowlist branch rejects `data.length < 4` before using it. |
| `uninitialized-local` | `GuardianThreatOracle.onReport` (`changes`) | Counter starting at zero. Benign. |
| `reentrancy-no-eth` | `GuardianPassportIssuer.claim` | Function is `nonReentrant`, and the external call is to the owner-configured passport SBT, not a user address. State written after the call (`claimedTokenOf`) is only read by `claim` itself. Low priority hardening: move the write before `mint`. |
| `reentrancy-no-eth` | `MaliciousToken.transferFrom` | Deliberately malicious **test helper**. Not deployed. Should move to `contracts/mocks/`. |
| `incorrect-equality` (×5) | View getters in `GuardianInterlockRegistry`, `GuardianPassportSBT`, `GuardianInsuranceLedger`, `GuardianThreatConsumer` | `== 0` existence/division-by-zero checks on stored values, not balance comparisons an attacker can manipulate. Benign. |
| `unused-return` (×2) | `GuardianCircuitBreaker.guardianProtected*` | Second tuple value of `isMalicious` intentionally ignored. Benign. |

## Low (21) and Informational (14)

- `timestamp` (12): 24h spend windows, card/attestation expiry. Validator timestamp skew of seconds does not matter at these granularities.
- `missing-zero-check` (9): constructor/admin setters. Owner-only; worth adding zero-address checks on the next redeploy.
- Informational: inline assembly (revert bubbling), low-level calls (the wallet call and the RIP-7212 P-256 precompile), missing explicit interface inheritance, loop gas costs, cyclomatic complexity.

## Follow-ups

1. Move `MaliciousToken.sol` and `GuardianProtectedVault.sol` into `contracts/mocks/` so they drop out of scope.
2. On the next redeploy: zero-address checks on setters, and write `claimedTokenOf` before `passport.mint` in `GuardianPassportIssuer.claim`.
3. Static analysis does not cover economic or cross-contract logic. A third-party audit is still required before real funds.
